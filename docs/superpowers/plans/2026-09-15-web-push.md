# Web Push to the specification (Part A) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A keyed UnifiedPush registration receives an RFC 8291 `aes128gcm` payload signed with RFC 8292 VAPID, registered over the API; a keyless one keeps receiving plaintext.

**Architecture:** `Target::UnifiedPush` grows a `keys: Option<WebPushKeys>`; `jobs::remind::push` encrypts when keys are present and sends a versioned JSON payload built from the owed rows. One VAPID keypair per instance lives in a new one-row `instance` table in the control database, generated on first boot. Three API routes register, read and unregister; Settings shows the registering device and marks keyless rows as legacy.

**Tech Stack:** Rust 2024, axum 0.8, sqlx/SQLite, `web-push-native` 0.5 (no default features) for RFC 8291/8030, `p256` 0.13 with `ecdsa` for RFC 8292, `base64` 0.23, wiremock for the transport tests.

**Spec:** `docs/superpowers/specs/2026-09-08-android-companion-design.md`, Part A.

## Global Constraints

- Every existing test in `src/jobs/remind.rs` stays green; the only edit allowed to one is the field a struct variant gained, never an assertion.
- Gotify does not change.
- A keyless `unifiedpush` row keeps receiving `"{title}\n{message}"` as a plain body.
- A payload that would exceed one 4096-byte record is refused, not truncated.
- No ranking code is touched. No offline harness exists; evidence goes in the commit message.
- UI copy on the Settings page: a term and a short gloss, never an explanatory sentence.
- Dependency choices are justified in a comment in `Cargo.toml`, as the rest of the file does.

## Decisions taken in brainstorming

**Crate.** `web-push-native = { version = "0.5", default-features = false }`. It is pure RustCrypto (`aes-gcm`, `hkdf`, `p256`, all versions already in the tree through openidconnect), implements RFC 8291's key agreement and RFC 8188's record layer against the final RFCs, and hands back an `http::Request<Vec<u8>>` that reqwest executes under engram's own redirect policy. Its `vapid` feature was refused: it brings `jwt-simple`, which adds about thirty crates (ML-DSA, secp256k1, Ed25519, an RSA shim) for a three-claim ES256 token. The alternative, `web-push` 0.11, sits on Mozilla's `ece` with an OpenSSL backend by default and carries its own HTTP client; this tree is rustls end to end.

**VAPID.** The signature is `p256::ecdsa::SigningKey` (RustCrypto, already in the tree; named directly in `Cargo.toml` with the `ecdsa` feature so the dependency is not borrowed from openidconnect's defaults). The JWT framing around it is two base64url JSON blobs and a dot, written in `src/jobs/webpush.rs`. The `sub` claim is `mailto:<user email>` when the user row has one and omitted otherwise; RFC 8292 says SHOULD.

**Instance table.**
```sql
CREATE TABLE IF NOT EXISTS instance (
  id            INTEGER PRIMARY KEY CHECK (id = 1),
  vapid_private TEXT NOT NULL,   -- base64url, the 32-byte P-256 scalar
  vapid_public  TEXT NOT NULL,   -- base64url, the 65-byte uncompressed point
  created_at    INTEGER NOT NULL
);
```
The row is written by `Control::ensure_instance` from both `connect` and `memory`, with `INSERT ... ON CONFLICT DO NOTHING` so two processes booting at once agree.

**Notify JSON.** `{"unifiedpush": {"endpoint", "p256dh", "auth", "device", "registered_at"}}`. `device` is the User-Agent of the PUT. A row with no `p256dh`/`auth` is legacy.

**Payload.**
```json
{ "v": 1, "kind": "due", "at": <wake>, "moments": [{"id","title","at"}], "more": <n> }
{ "v": 1, "kind": "notice", "at": <now>, "title": "…", "body": "…" }
```
`due` is the ladder's message; `notice` is what `notify_now` and the Settings test button send.

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct VapidKeys { pub private: String, pub public: String }

pub async fn ensure_instance(&self) -> Result<()> {
    use p256::elliptic_curve::sec1::ToEncodedPoint;
    let secret = p256::SecretKey::random(&mut p256::elliptic_curve::rand_core::OsRng);
    let private = URL_SAFE_NO_PAD.encode(secret.to_bytes());
    let public = URL_SAFE_NO_PAD.encode(secret.public_key().to_encoded_point(false).as_bytes());
    sqlx::query("INSERT INTO instance (id, vapid_private, vapid_public, created_at) VALUES (1, ?, ?, ?) ON CONFLICT (id) DO NOTHING")
        .bind(private).bind(public).bind(super::now()).execute(&self.pool).await?;
    Ok(())
}

pub async fn vapid(&self) -> Result<VapidKeys> { /* SELECT the row */ }
```
