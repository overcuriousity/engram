# Decide Web UI (spec 1, stage 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Decide` sits beside `Ask` in the workspace: one question answered yes/no, from named options or on a scale, with weights as bars in the pane and the evidence, each note with its own pick, in the rail.

**Architecture:** The transport is ask's: a POST parks the request and returns an id, an `EventSource` spends it. The server renders every fragment (rail rows as they are read, then the result and the final rail); the client only places them. Bars are small inline SVGs, because the CSP forbids inline styles and an attribute is not a style. Pure client logic lives in a tested ES module; the DOM driver sits in `assets/app.js` beside `askDriver`, whose helpers it shares.

**Tech Stack:** axum, askama, htmx, vanilla JS (`node --test`), layered CSS built by `build.rs`, a headless-Chrome harness under `tests/browser/`.

**Spec:** `docs/superpowers/specs/2026-11-13-decide-1-verb-design.md`, sections "Web UI" and "What a verdict does", and the Anti-goals. Part 3 of 4 on branch `feat/decide`; parts 1 and 2 are done before this starts.

## Decisions this plan makes

- Shortcut: `Alt`+`↵` presses Decide; shown in `_keyhint.html` and the `?` dialog. `Esc` closes the answer row.
- The POST body is JSON in `/api/v1/decide`'s shape, parsed by the same `DecideBody`. The single question's key is `verdict`.
- Web frames: `retrieved` `{"passages": n}`; `read` `{"rank","of","bearing","row": html}`; `done` `{"event_id","html","rail","rail_head"}`; `error` plain text.
- Progress copy: `Reading 3 of 8`, then `Weighing 6 together` once the last read is in and any bear; nothing between the last read and `done` when none bear.
- A bar is `<svg class="bar-track" viewBox="0 0 100 4" preserveAspectRatio="none" aria-hidden="true">` with a `rect.bar-fill` whose `width` is the weight and a `rect.bar-prior` whose `x` is the prior's weight; the text equivalent is an `oc-sr-only` span: `keep: 81 of 100, 55 without notes`.
- The "A or B?" pre-fill is not built.
- Phone, below 48rem: the answer row's choices wrap; each option is its own line, name above its description.
- Rail rows of a decision open in the pane like search hits (`hx-get` on `/ui/artifacts/{id}`), not in a new tab.

- The verdict bar has four faces: unjudged and held (`Right`, `Wrong`, `Nothing here`); unjudged and not held (`Right`, `Wrong`); wrong among three or more answers with none named yet (`Which is it?`, a button per remaining answer, `Not sure`, `Undo`); judged (`judged right`, or `judged wrong · it is switch`, and `Undo`).

## Review Focus

1. Eight options with 40-character names and a result with those names, at 390 px: nothing scrolls sideways. Task 6.
2. A second Decide pressed while the first is reading: the first stream is closed and its late frames are ignored. Task 5 and Task 6.
3. Options left blank, one option only, a duplicate name: Decide does not post; the row says what is missing in one line. Task 3.
4. A decision parked by one person cannot be spent by another, nor twice. Task 2.
5. An option name with `<`, `&`, quotes: escaped in the result, the rail and the screen-reader text. Task 1.

### Task 3: The client's pure logic

**Files:**
- Create: `assets/js/decide.js`, `assets/js/decide.test.mjs`

**Interfaces:**
- Produces (ES module exports; when `document` exists it also sets `globalThis.engramDecide` to the same object, so the non-module `app.js` can reach it):
  ```js
  // row: { kind: "noul" | "choice" | "score", options: [{ name, description }], levels: [string] }
  export function decideBody(q, row)      // -> the /ui/decide body as an object, for reading
  export function bodyText(q, row)        // -> the same body as text, criteria in row order; this is what is posted
  export function problem(q, row)         // -> "" when it can be sent, else one line saying what is missing
  export function progressText(read, of, bearing)  // "Reading 3 of 8"; when read === of and bearing > 0: "Weighing 6 together"; else ""
  export const LIMITS = { options: [2, 8], levels: [2, 10] }
  ```
  `decideBody` trims names, descriptions and levels and drops rows that are entirely blank. `noul` sends no `questions`. `choice` sends `{"verdict": {"type": "choice", "criteria": {name: description}}}` built in row order; `score` sends `criteria` as the array.

  `problem` copy, exactly: `Type a question first`; `Name at least two options`; `Use each option once`; `At most eight options`; `Name at least two levels`; `At most ten levels`.
