## What is left

Rewritten later on 2026-09-19 by the session that took this list up, on a
second machine (`altiera`) that had no Android SDK, NDK, libclang or model

   the core (Rust Android target, `cargo-ndk`, NDK 28.2.13676358, libclang,
   `-Pengram.native=1`) and refuses an APK without `libengram_android.so`;
   `ci.yml` has a `contained` job, clippy and `--lib` tests. The cargo half of
   the release path was run here from a bare NDK and works. The Gradle half was
   not: no SDK. Watch the first push, and the first release after the merge.
2. **The Kotlin tests have not run since the Gemma 4 E2B entry.** One data
   entry and a count from 2 to 3 in `ModelManifestTest`; run
   `./gradlew :core:testDebugUnitTest :app:testDebugUnitTest` where there is
   an SDK.
3. **The phone's language to `LocalTranscriber` — left as a decision.** It
   means a fourth argument through `Transcriber` and its three implementors,
   and it forces `Accept-Language` on whisper: someone whose phone is in
   English and who dictates in German gets worse words, not better. Whisper's
   own detection stays until the device pass says short notes are misheard.
4. **The `.so` stays at 65 MB.** Measured: `opt-level = "s"` for the engram
   crate gives 62,756,832 against 65,420,608, four percent, and the embedded
   web assets are 832 KB. No symbol is over 2 MB; the weight is llama.cpp's
   code for every architecture it knows. Not worth a slower core. Cutting
   architectures out of llama.cpp would be the real lever and is a fork.
5. **The reranker's ordering against `bge-reranker-v2-m3` over the live
   base** was not tried: it needs the live base and the candidates.
6. **The phone:** `docs/superpowers/plans/2026-09-19-contained-7-device-pass.md`.

## Done since

- **Release and CI**, as above. **`ANDROID_NDK`**: llama.cpp's build reads
  that name and not `ANDROID_NDK_HOME`, and without it takes the newest NDK
  under `~/Android/Sdk` — or, on a runner, the runner's own. The Gradle task
  now sets both.
- **Thinking parted from the answer** in `LocalCompleter` (`ThinkSplit`), as
  `Delta::Reasoning`. Qwen3.5-2B under its file's template does not think in
  process — it answers within 64 tokens — so this is for models that do;
  Qwen3-0.6B does, and spends a 64-token ceiling on nothing else.
- **Gemma 4 E2B** in the manifest, not a default, 3.1 GB at Q4_K_M.
- **Both READMEs** name contained mode.
- **Can a 2B follow the synthesis instructions? Yes, with thinking off.**
  Qwen3.5-2B Q4_K_M behind llama.cpp's server, the desktop example pointed at
  it (`ENGRAM_ASK_URL`, `ENGRAM_ASK_MODEL`), three notes, one German:
  - *Thinking on* (the server's default with `--jinja`): every window spent
    the whole 4096-token ceiling thinking, the JSON came back cut off, the
    repair did the same, the jobs failed into retry. About 31 tokens a second
    on this desktop; minutes per three-sentence note.
  - *`--reasoning-budget 0`*: three of three windows parsed at the first try,
    no repair, all `ready` in under a minute. Titles, categories and tags
    were sensible, the German note stayed German, the shell note was split
    into two procedures.
  - What it got wrong: no moment from "am 14. Oktober zwischen 8 und 12 Uhr"
    or "ready Wednesday"; the shell note read as `remind` with a null rule,
    which `judgement` refused; "kpartx is the older way" was dropped in the
    rewrite, and one procedure gained a clause nobody wrote.
  So an in-process synthesizer is not ruled out by the model, and it would
  have to run with thinking off. Three notes is not an evaluation: before the
  refactor, run the eval set through the same arrangement. The device tiers
  in `contained.rs` send nothing that turns thinking off; an endpoint serving
  a small reasoning model will fail as above until they do.

## Things worth knowing

- **A capture's `ready` is not final until the queue has settled.** Before part
  6, synthesis units failed against port 9, retried five times, and only then
  did the capture read `partial`; two earlier reports of "all `ready`" were
  early readings. Since part 6 those units are held and nothing fails: three
  captures stayed `ready` for five and a half minutes with
  `waiting_generation: 3` and `failed: 0`. Count `raw` as in progress.
- **The phone's ask model answers questions and reads nothing.** There is no
  in-process `Synthesizer`. Model work in contained mode runs through an
  endpoint or waits. An endpoint serves both ask and synthesis.
- **whisper.cpp and the llama pin are a matched pair.** `whisper-rs-sys` was
  not used: it vendors ggml 0.9 and cannot be given another. v1.9.2 is the
  newest whisper.cpp written against a ggml at or below llama.cpp's 0.19;
  v1.9.3 wants 0.20. `llama-cpp-sys-2` is named in `Cargo.toml` only because
  Cargo hands `DEP_*` to direct dependents. `vendor/whisper.cpp/README.md` says
  how to re-match them.
- **`LiveServerTest` never checks a capture's status.** It passed 5 of 5 while
  every capture was failing. Search through the API yourself.
- **Refreshing the Android fixtures rewrites all fifteen.**
  `ENGRAM_WRITE_ANDROID_FIXTURES=1` churns every id and timestamp; keep only
  the file whose shape changed and restore the rest.
- **The app module does not see Room**, on purpose. Receivers ask `Engram`
  (`reminders()`, `reminder(id)`), not the database.
- **`Engram`'s constructor runs under Robolectric with no WorkManager**, which
  is why the background pass is scheduled from `MainActivity.onResume` and not
  from there.
- **What has no test:** `Engram.switch` itself, `ModelLine`, `DownloadScreen`,
  the three Settings sections, the gates in `Nav`, the offers' wiring in
  `AskScreen` and `SearchScreen`, the download and background workers, the
  alarms and both receivers. They sit on WorkManager, the keystore or a running
  core. Their stateless halves and their rules are tested.
- **One oddity, left alone:** on a three-capture base an English query ranked
  two `weak` English hits (0.88, 0.63) above the one relevant German hit
  (0.55). Probably rank fusion on a tiny base.
- **Do not `git stash` in this checkout to compare with "before".** There is a
  stash of the owner's, `roadmap edits pre-rebase`; a stash on a clean tree
  saves nothing and the pop that follows applies that one. Use `git blame`.

## Running things

```bash
# Rust, with the model-backed tests on
export ENGRAM_TEST_MODELS=$HOME/.cache/engram-test-models   # embed.gguf rerank.gguf ask.gguf speech.bin speech.wav
cargo test --features contained --lib

# The core on the desktop; prints origin= and token=
cargo run --features contained --example contained -- /tmp/engram-contained $ENGRAM_TEST_MODELS
# stop it with:  pgrep -x contained | xargs -r kill      (never pkill -f with its path)

# The Android client against it (seed three captures through POST /api/v1/corpora first)
cd android && ./gradlew :core:testDebugUnitTest --tests '*LiveServerTest*' \
  -Pengram.live.origin=... -Pengram.live.token=...

# The native library. Everyday cargo is Fedora's; the Android target is on rustup `stable` only.
export PATH=$HOME/.cargo/bin:$PATH ANDROID_NDK_HOME=$HOME/Android/Sdk/ndk/28.2.13676358 ANDROID_NDK=$ANDROID_NDK_HOME
cd android/native && cargo +stable ndk -t arm64-v8a --platform 29 build --release
cd android && ./gradlew :app:assembleRelease -Pengram.native=1

# Pictures of the new screens, to app/build/pictures/
cd android && ./gradlew :app:testDebugUnitTest --tests '*PicturesTest*' -Pengram.pictures=1
```
